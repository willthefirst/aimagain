{# Shared clinician-row macros — used by every list of clinician directory entries (the underlying Python model class is still `Provider`; only the user-facing surface flipped in #642 PR 4). Lives in `_shared/` rather than `providers/` because four templates across three clusters render the same row (`/clinicians`, `/users/me/favorites`, `/users/{id}/clinicians`, and the embedded "Clinicians" section on the user detail page). Cross-cluster template imports aren't allowed (see ../README.md "Layering rule"), so the shared shape goes here. The macros themselves keep the `provider_*` identifiers because callers haven't been renamed (and the framework templates layer doesn't depend on the entity-name flip). Filters for the `/clinicians` index are declared on `PROVIDER_ENTITY.filters` and render on the dedicated `/clinicians/search` page (via `views/search.html`) — there's no clinician-specific filter partial to maintain. After #642 PR 3 each cell reflects **every** affiliation the Provider holds — not just the primary one. - Practice cell: one anchor per affiliation pointing at the owning Organization (`/organizations/{aff.org_id}`), joined by `" · "`. Two affiliations at the same Org keep both chips (they may be different locations); the cell intentionally does not dedupe by `org_id`. The `` keeps `class="primary"` so the responsive mobile-stack pattern (see `_shared/index_table.html` and `base.html` #578) still treats the cell as the row's headline. - Location cell: `"City, ST"` per affiliation, joined by `" · "`, with adjacent duplicate strings deduped (a clinician with two affiliations both in Brooklyn, NY renders one chip — see the `seen` set below). - Insurance cell: rendered from `src.domain.logic.providers.view._insurance_summary`, which unions in-network carriers, out-of-network acceptance, and sliding-scale posture across every affiliation.
