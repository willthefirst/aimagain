{# `form_with_errors` — wraps an opted-in form's `
` tag with the hx-* attributes the form-error rerender path requires, plus the `form_banner()` placement. Templates supply the field inputs inside a `{% call form_with_errors(...) %}` block. Before this macro, every opted-in form template wrote nine lines of mechanical wiring: {%- from "_shared/form_banner.html" import form_banner with context -%} {{ form_banner() }} ...
With this macro, that collapses to: {%- from "_shared/form_meta.html" import form_with_errors with context -%} {% call form_with_errors(action="/auth/register", method="post", json_enc=true) %} ... {% endcall %} The macro bakes in: - `hx-{method}=""` — the submit URL. - `hx-target="this" hx-swap="outerHTML show:window:top"` — the swap spec for BOTH success and error. The `show:window:top` modifier scrolls the viewport to the top of the page after the swap so the re-rendered `form_banner()` slot is visible. Without it the error swap happens in place and the user — still scrolled at the submit button — sees no movement and thinks nothing happened; the summary + highlighted fields are above the fold. GOTCHA — the swap spec (style AND modifiers) lives ONLY on `hx-swap`; there is deliberately no `hx-swap-4xx`. The `response-targets` extension reads only `hx-target-` attributes: on a 4xx it sets `evt.detail.shouldSwap = true` and `evt.detail.target`, and never touches the swap style. htmx then takes the swap spec from the element's plain `hx-swap`. So `hx-swap-4xx` is read by nothing (neither the extension nor htmx core) — putting the scroll modifier there silently no-ops. The repo used to set `hx-swap-4xx="outerHTML"` on every opted-in form; it only ever "worked" because the value happened to match `hx-swap`. It's been removed as dead. We use `show:window:top` (scroll viewport to 0) rather than `show:top` (scroll the *swap target* into view) because the swap is `outerHTML` — it replaces the form element, so htmx can't reliably re-resolve the now-removed target; scrolling the window is unconditional and correct here because every form using this wrapper sits at the top of its page. On a successful submit `mount_create` returns `HX-Redirect` (htmx navigates, no swap), so the modifier only ever fires on the error re-render. - `hx-target-4xx="this"` — activates `response-targets` so 4xx rerenders swap in place (the swap *style* still comes from `hx-swap` above — see the gotcha). - `hx-ext="json-enc"` (when `json_enc=true`) — for endpoints that take JSON bodies (`/auth/register`, `/auth/forgot-password`). - `{{ form_banner() }}` — the form-level alert slot. What the template still imports itself: - `text_field`, `select_field`, etc. from `_shared/form_fields.html` `with context` — Jinja macros that depend on caller-scoped context can't be hoisted into a wrapper macro (the wrapper's imports are scoped to the wrapper, not the caller). The contract pin (`test_form_error_handler_contracts.py`) used to check the four hx-* attributes individually; after this PR it can simplify to "every opted-in template uses `form_with_errors`" once every form has migrated. For now both rules coexist. `with context` is required when importing this macro so the `form_banner()` call inside it can read `form_banner_text` from the render context. #} {%- from "_shared/form_banner.html" import form_banner with context -%} {% macro form_with_errors(action, method="post", json_enc=False, extra_attrs="") -%} {# `hx-=` is built as a string and emitted with `|safe` because djlint mangles a templated attribute *name* (`hx-{{ method }}`) — it sees the dynamic name as a value and line-wraps it. Same workaround as the entity forms in `posts/_form_referral.html` / `posts/_form_clinician_opening.html`. #} {%- set _hx_method_attr = 'hx-' ~ method ~ '="' ~ action ~ '"' -%} {%- set _json_ext = 'hx-ext="json-enc"' if json_enc else '' -%}
{{ form_banner() }} {{ caller() }}
{%- endmacro %}
