# Persistence: SQLAlchemy + DI primitives

SQLAlchemy + repository primitives + DI registry. Generic; nothing here knows what a "user" or "post" is.

## Files

- `base_model.py` — `Base = declarative_base()` plus `BaseModel(Base)` with the common entity fields (`id` UUID PK, `created_at`, `updated_at`, `deleted_at`). Domain models inherit from `BaseModel`; detail-table models with no surrogate id inherit from `Base` directly. Re-exported through [`../../domain/models/__init__.py`](../../domain/models/__init__.py) so domain code says `from src.domain.models import Base, BaseModel, metadata`.
- `mixins.py` — Column-group mixins shared by 2+ ORM models. `LocationMixin` (the `(city, state, zip)` triple, used by `Clinician` and `ReferralDetail`) is the only one today; its wire-/audit-layer counterpart is the `Location` Pydantic value object at [`../../domain/logic/value_objects/`](../../domain/logic/value_objects/). Mixins own column declarations only — CHECK constraints stay on the consuming table because constraint names are table-prefixed. Columns use `@declared_attr` so each consumer gets its own `Column` object (a bare `Column(...)` on a mixin is shared across subclasses and attaches only to the first consumer's table).
- `base_repository.py` — `BaseRepository`, the parent class every domain repository extends. Public methods: `get_by_model_id`, `create`, `delete`, `patch`, `add_child`, `create_polymorphic`, `list_default`. Domain repos add custom-SQL methods only when the standard primitives can't express the query.
- `polymorphic.py` — `DiscriminatorRegistry[S]`, generic bookkeeping for any polymorphic entity (the `kind`-discriminated parent + per-variant detail table pattern). Posts is the only consumer today; the registry exists so a second polymorphic entity is a clean import rather than a re-derivation.
- `dependencies.py` — FastAPI `Depends` resolver factory. Every repository class is registered in `_REPO_TYPES`; resolvers are generated by `_make_repo_resolver` and exposed as `get_<entity>_repository`. The mount layer (`../dispatch/resource_routes.py`) consumes the type→resolver registry to synthesize handler signatures.

## Adding a new repository type

Add the class to `_REPO_TYPES` in `dependencies.py`. The public `get_<entity>_repository` binding is generated automatically. Forgetting it raises `UnknownRepoTypeError` at mount time — loud and immediate.

## Tests
